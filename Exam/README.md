# Зачет

Форма промежуточной аттестации — **зачет**. Результат выражается только как
«зачтено» или «не зачтено».

## Итоговые 100 баллов

| Компонент | Максимум |
|---|---:|
| 8 лабораторных работ | 48 |
| 4 лучших устных сообщения | 8 |
| Групповая Git-игра | 4 |
| Курсовая работа | 40 |
| **Итого** | **100** |

Каноническая машиночитаемая модель находится в
[`course-spec/assessment-model.yml`](../course-spec/assessment-model.yml).

## Условия результата «зачтено»

Необходимо одновременно:

1. набрать не менее 60 из 100 баллов;
2. представить все восемь лабораторных работ;
3. выполнить групповую Git-игру;
4. получить за курсовую работу не менее 16 из 40 баллов;
5. подтвердить авторство и понимание на защите с изменением условий.

Если хотя бы одно условие не выполнено, выставляется «не зачтено».

## Подтверждение авторства

[Теоретические вопросы](exam_theory.md) и
[практическое задание](exam_practice.md) не дают дополнительных баллов сверх
100. Они используются преподавателем для проверки понимания, способности
диагностировать проблему и безопасно изменить собственное решение.

Изменение выбирается из равноценных вариантов: новый формат данных,
дополнительный endpoint, иной критерий сортировки, ограничение памяти, отказ
сервиса или новый конфликт Git. Использование ИИ во время индивидуальной защиты
допускается только по прямому разрешению преподавателя.

## Апелляция

Апелляция должна ссылаться на конкретный критерий YAML-рубрики и проверяемый
артефакт. Автоматическая проверка не отменяет экспертного решения: корректная
альтернативная реализация может быть оценена вручную.
