# Семестровый релиз

Формат тега: `YYYY-season-vMAJOR.MINOR`, например `2026-fall-v1.0`.

Перед релизом:

1. обновите версии зависимостей и контрольные суммы данных;
2. сравните YAML-рубрики с КИМ;
3. прогоните starter-проекты на чистой среде;
4. проверьте публичные и закрытые тесты на эталонном решении;
5. обновите `CHANGELOG.md`;
6. соберите документационный сайт;
7. подпишите тег и опубликуйте GitHub Release.

Нельзя менять правила оценивания активного потока без объявления миграции.
Критическое исправление выпускается отдельным patch-релизом.
